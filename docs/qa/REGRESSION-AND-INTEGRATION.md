# 回归与联调策略

## 当前基线

M0 仅规划，产品测试执行状态均为 **NOT_RUN**。用户拥有 Mac/iPad，后续协调构建与真机。Windows 文档检查不等于 Swift 编译、模拟器或 Apple Pencil 验证。

## 后端交接回路

1. 开发按 `SUBMISSION-TEMPLATE.md` 提测，附唯一任务 ID、实际基线、契约版本、变更范围、测试命令及原始结果，释放文件所有权。缺契约/代码/可用环境时 QA 记录 BLOCKED 原因，PM 安排恢复。
2. QA 读取职责、看板、交接并记 READ_ACK、ACCEPTED。PM 将任务置 QA_IN_PROGRESS；QA 不修改业务实现或开发证据。
3. 先执行受影响单元/持久化与接口契约：范围构造、引用校验、索引状态、取消/并发、错误传播、持久化重启。mock Provider 测分片、截断、错误、超预算，真实 Provider 单独验证兼容性及回答依据。
4. 失败登记缺陷，附最小复现与证据，PM 路由开发。开发修复后新提测；QA 复测原问题并执行影响范围回归，附结果；只有 PM 才做阶段验收和看板收口。

不默认“后端”是远程服务：原生本地数据/文档处理/AI 接入模块同样受契约和回归约束。若采用服务端，另验证鉴权与文档隔离。

## 外部前端联调

M0-UI 设计已交付，独立审阅见 `M0-UI-REVIEW.md`；具体新增步骤见 `UI-INTEGRATION-CASES.md`。存在契约冲突时先由 PM 路由设计修订，不能将设计交接等同于可运行前端或产品验收。

用户通知 UI/前端完成 → PM 收到文件清单与契约交接 → QA 接收 → 构建与集成。不得因为在共享目录看到文件就抢写或宣告接收。

最小联调路径：系统导入 PDF → 打开及缩放 → Pencil 批注保存/重开 → 选择文本 → 页/章/选区助学 → 真实问答 → 引用定位 → 全文学习视图 → 继续原文阅读。P1 Notes 就绪后接保存编辑闭环。

重点验证前后端字段一致：doc/page/chapter ID、页码从 0 还是 1 开始、PDF 坐标系与页面旋转、selection 空值语义、scope 范围、请求与取消 ID、流事件顺序、来源验证状态、错误与重试、索引就绪状态。接口不一致归契约所有者确认后串行修改，不能各自改一端。

原生 UI 还需检查横竖屏、分屏可用尺寸、AI 面板开关不跳阅读位置、Pencil 与手指手势、背景/前景切换、系统终止后已保存数据恢复。手写跟手、掌托与真实 PDF 压力场景必须在真实 iPad 测试；性能数值先由项目确定目标设备与门槛，不使用模拟器伪证。

## 结果与门禁

- PASS：指定环境与输入实际执行且符合预期。
- FAIL：实际执行不符合预期，有复现证据。
- BLOCKED：本轮已准备执行但缺前置条件，写明恢复条件、责任人。
- NOT_RUN：尚未执行，包括 M0 全部产品测试。

每个结果包含矩阵 ID、构建/契约、时间(+08:00)、环境类别、设备与系统、输入、步骤、预期、实际、证据。mock 和真实记录分开，不能合并成一个 PASS。P0 未运行或失败不得写“版本验收通过”；PM 可验收 M0 文档产物，但不能替代产品验收。

风险回归优先级：数据丢失/笔迹错位/密钥泄露 → 阅读与保存 → 来源错引及串文档 → AI 失败恢复 → 全文导航 → P1 功能。每次回归依据改动影响选择范围，避免无理由重复全量。
